# 评估报告模板

按以下顺序输出。保持证据化和可行动，不写人格诊断。

## 1. 一句话结论

写清当前能力阶段、最强项和最主要瓶颈。

示例结构：

> 当前为 L4 系统化使用者：已经能让 AI 进入真实执行，但验证方式仍更依赖人工发现问题，限制了进一步放权。

## 2. 总览

- 评估日期：
- 样本范围：
- 任务数：
- 工作类型：
- 复杂任务数：
- 已验证结果数：
- 总分：`__/100`
- 评级：
- 前沿行为吻合度：
- 可信度：`__/100（低/中/高）`
- 评分覆盖率：`__%`
- 基准版本：

可信度不足时先说明限制，再给分数。不要把精确数字写成精确真相。

## 3. 七维得分

| 维度 | 得分 | 主要证据 | 限制分数的证据 |
|---|---:|---|---|
| 目标与问题定义 | _/4 |  |  |
| 上下文与约束 | _/4 |  |  |
| 拆解与委派 | _/4 |  |  |
| 工具与执行杠杆 | _/4 |  |  |
| 验证与批判判断 | _/4 |  |  |
| 迭代与失败恢复 | _/4 |  |  |
| 沉淀与复用 | _/4 |  |  |

证据使用任务摘要，不大量复制用户原话，不包含隐私或凭证。

## 4. 与前沿使用方式的比较

只写三类内容：

- 已经达到的行为；
- 最明显的差距；
- 当前不能证明的能力。

不要使用没有数据支持的百分位。

## 5. 可能高估与低估

- 可能高估：至少一条。
- 可能低估：至少一条。

用于公开评分的不确定性说明，不要藏在内部推理中。

## 6. 改进实验

最多三个，优先一个。

### 实验名称

- 适用场景：
- 唯一动作：
- 持续周期或次数：
- 通过标准：
- 预计改变的维度：

动作必须能进入真实工作。例如“每个重要任务开工前先写三条验收标准”，而不是“学习上下文工程”。

## 7. 复测

说明何时复测、使用哪些相同任务类型，以及除了总分还要检查哪些真实结果。

推荐 2–4 周或累计 10 个新任务后复测。
